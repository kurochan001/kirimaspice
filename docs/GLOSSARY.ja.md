## ネットリスト

| 用語 | 意味 |
| --- | --- |
| <a id="netlist"></a>ネットリスト | 回路と、行う解析を書いたテキストファイル。kirimaspice は SPICE のネットリストを読み、SPICE の方言が違うところでは ngspice に合わせる（[NETLIST_CONVENTIONS](spec/NETLIST_CONVENTIONS.ja.md)） |
| タイトル行 | ネットリストの最初の空でない行。中身は問わない |
| 素子 | デバイスを置く行。最初の文字で種類が決まる：`R1`、`V1`、`M3`、`X2`。素子名は大文字と小文字を区別する |
| <a id="directive"></a>ディレクティブ | `.` で始まる行：`.MODEL`、`.TRAN`、`.PARAM`。読むだけでプログラムが使わないものもある（[リファレンスマニュアル](REFERENCE_MANUAL.ja.md#ディレクティブ)） |
| <a id="node"></a>ノード | 素子の行で名前を付ける接続点。ノード名は大文字と小文字を区別する |
| <a id="ground"></a>グラウンド | 基準のノードで 0 V。`0`、または大文字小文字を問わない `gnd`。kirimaspice の中ではノード 0（`NODE_GND`） |
| 継続行 | `+` で始まり、前の行の続きになる行 |
| <a id="model-card"></a>モデルカード | `.MODEL` の行。名前を付けたデバイスのパラメーターの組。名前は大文字と小文字を区別せず、それを使う `D`、`Q`、`M`、`Z` の素子より後に置いてもよい |
| `LEVEL` | MOSFET のモデルを選ぶモデルカードのパラメーター：1、3、BSIM1、BSIM3、BSIM4 など（[リファレンスマニュアル](REFERENCE_MANUAL.ja.md#モデル)） |
| <a id="subcircuit"></a>サブサーキット | `.SUBCKT` と `.ENDS` の間に定義し、`X` 素子で置く回路。名前は大文字と小文字を区別しない。中のノードと素子は `X1.n1` のような名前になる。中で展開する素子は一部だけ（[リファレンスマニュアル](REFERENCE_MANUAL.ja.md#素子)） |
| <a id="parameter"></a>パラメーター | `.PARAM` で定義し、`{...}` の式で使う名前。`.FUNC` は `.PARAM` の式で使う関数を定義する |
| 式 | 波かっこ `{...}` で囲んだ値。ExprTk のライブラリで評価する。中では倍率を受け付けない |
| <a id="scale-factor"></a>倍率 | 数に付けて桁を表す接尾辞で、大文字小文字を問わない：`T`、`G`、`MEG`、`K`、`MIL`、`M`（ミリ）、`U`、`N`、`P`、`F`、`A`（アト）。メガは `MEG` |

## 電源とデバイス

| 用語 | 意味 |
| --- | --- |
| 独立電源 | 値が回路に左右されない電圧源（`V`）と電流源（`I`）。DC の値を持ち、AC の入力と過渡解析の波形（`PULSE`、`SIN`、`EXP`、`PWL`、`SFFM`）を持てる（[リファレンスマニュアル](REFERENCE_MANUAL.ja.md#電源)） |
| <a id="ac-input"></a>AC の入力 | 行に `AC [<振幅> [<位相>]]` がある電源。AC 解析を駆動するのは、このような電源だけ |
| 制御電源 | 値が電圧（`E` は電圧を、`G` は電流を出す）か、電圧源の電流（`H` は電圧を、`F` は電流を出す）で決まる電源 |
| <a id="behavioural-source"></a>ビヘイビア電源 | 電圧か電流が、ノード電圧と `TIME`（過渡解析の時刻）の式で決まる `B` 素子 |
| <a id="branch-current"></a>枝電流 | 電圧源、`E`、`H`、電圧の形の `B` 電源の電流で、それ自身を未知数として解く。`+` 端子から電源の中を通る向きを正とするので、電流を供給している電源の電流は負になる |
| レベル 1 の MOSFET | 2 乗則の MOSFET のモデル。パラメーターは `KP`、`W`、`L`、`VTO` とノイズのパラメーター。基板効果とチャネル長変調はない |
| BSIM3、BSIM4 | Berkeley の短チャネル MOSFET のモデル。BSIM4 のコードは BSIM4 4.8.3 に基づき、その ECL-2.0 の表示を残している（[THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.ja.md)） |
| <a id="mutual-inductance"></a>相互インダクタンス | 2 つのインダクタを係数 k で結合する `K` 素子。M = k·√(L1·L2) |
| <a id="lossless-line"></a>無損失線路 | 特性インピーダンス `Z0` と遅延 `TD` を持つ伝送線路の `T` 素子。特性曲線法で計算する |
| 有損失線路 | 単位長さあたりの抵抗、インダクタンス、キャパシタンス、コンダクタンスを持つ伝送線路の `O` 素子 |

## 解析

| 用語 | 意味 |
| --- | --- |
| <a id="operating-point"></a>動作点 | キャパシタを開放、インダクタを短絡とした回路の DC の解（`.op`） |
| <a id="dc-sweep"></a>DC スイープ | 電源をある範囲で刻んだときの動作点の列（`.DC`）。電源が 2 つなら、2 つ目の値ごとに 1 つ目を掃引する |
| <a id="transient"></a>過渡解析 | 時間を追った解（`.TRAN`）。動作点から、`UIC` を付ければ `.IC` の値から始める |
| <a id="ac-analysis"></a>AC 解析 | 動作点で線形化し、AC の入力で駆動した、周波数ごとの小信号の応答（`.AC`） |
| 温度スイープ | `.TEMP` に並べた各温度での、すべての解析。値が 1 つなら `.OPTIONS TEMP` と同じ（[リファレンスマニュアル](REFERENCE_MANUAL.ja.md#ディレクティブ)） |
| <a id="fourier"></a>フーリエ解析 | 過渡解析の最後の 1 周期での、信号の高調波と THD（`.FOUR`）。過渡解析の後に表示する |
| <a id="uic"></a>`UIC` | 「初期条件を使う」。`.TRAN` の行に書くと、過渡解析を動作点ではなく `.IC` の値から始める。`UIC` がないと、動作点で `.IC` のノードをその値に固定する |
| ライブラリだけの解析 | ノイズ、伝達関数、極零点、ひずみ、感度、S パラメータ、モンテカルロ、ワーストケース、最適化。ライブラリとそのテストにはあるが、プログラムは実行しない（[設計](ARCHITECTURE.ja.md#ライブラリにあるほかの解析)） |

## 数値計算の方法

| 用語 | 意味 |
| --- | --- |
| <a id="mna"></a>MNA | 修正節点解析。ノードごとに 1 つ、[枝電流](#branch-current)ごとに 1 つの未知数を持つ連立方程式 |
| <a id="stamp"></a>スタンプ（書き込み） | 今の解について、デバイスが MNA の方程式に書き込むもの。行列にはコンダクタンスを、右辺には電流を書く。解析ごとに書き込みのメソッド（`stamp_dc_nonlinear`、`stamp_transient`、`stamp_ac`）があり、どれも同じモデルのコードを評価する（[設計](ARCHITECTURE.ja.md#デバイス)） |
| ニュートン・ラフソン法 | 非線形の回路を、そのときの推定値のまわりで線形化して解くことを繰り返す方法。収束の判定は `RELTOL`、`ABSTOL`、`VNTOL`、回数の上限は `ITL1` と `ITL4` |
| `GMIN` | 方程式を解けるようにするための、グラウンドへの小さなコンダクタンス（既定 10⁻¹² S） |
| 収束を助ける方法 | gmin ステッピング、ソースステッピング、動的 gmin、連続法、疑似過渡。そのままの反復で動作点が求まらないときに使う方法で、どれも `.OPTIONS` で有効にする |
| <a id="klu"></a>KLU | 反復のたびに線形方程式を解く、SuiteSparse の疎行列 LU ソルバー。システムのものを動的にリンクする |
| <a id="integration-method"></a>積分法 | 過渡解析の 1 ステップで、キャパシタとインダクタの微分を方程式にする方法：後退オイラー法（1 次）、台形則（`trap`、既定）、BDF2（`gear`）、BDF3（`gear3`）、TR-BDF2。プログラムは、どの方法でも最初のステップを後退オイラー法で計算し（BDF2 では最初の 2 ステップ）、BDF3 はその後 BDF2 のステップで始める |
| コンパニオンモデル | 1 つの時間刻みのあいだ、キャパシタやインダクタを、積分法から決まるコンダクタンスと電流源に置き換えたもの |
| <a id="lte"></a>LTE | 局所打ち切り誤差。1 ステップで加わる誤差で、キャパシタの電荷とインダクタの磁束（結合インダクタでは結合した磁束）から見積もる |
| <a id="time-step"></a>固定刻みと可変刻み | プログラムは `tstep`（`tmax` が短ければ `tmax`）で刻み、電源の角にも刻みを合わせる。ライブラリには LTE から刻みを選ぶ可変刻みの経路もあるが、プログラムは使わない |

## 出力

| 用語 | 意味 |
| --- | --- |
| <a id="raw-file"></a>SPICE3 raw ファイル | SPICE3 と ngspice の波形のファイル。ASCII（`--raw-out`）とバイナリ（`--raw-binary-out`）がある。解析ごとに 1 つのプロットで、変数を並べたヘッダの後に、点ごとに変数 1 つにつき値が 1 つ続く |
| スケールの変数 | プロットの最初の変数で、ほかの変数はこれに対して並ぶ：`time` や掃引する電源 |
| <a id="ssf"></a>SSF | kirimaspice 独自のバイナリの波形形式（`-o`）。データのブロックは zstd で圧縮する。仕様はまだ公開していない |
| AC の CSV | AC 解析のテキストファイル `<base>_ac.csv`。周波数ごとに、各ノード電圧の実部、虚部、dB の振幅、位相を並べる |
| WAV の出力 | 過渡解析の結果を音声として書いたもの（`--wav-out`）。ノードごとに 1 チャンネル、±1 V が最大振幅 |

## プロジェクトと進め方

| 用語 | 意味 |
| --- | --- |
| kirimasim | 姉妹プロジェクトの SystemVerilog シミュレータ。波形の形式の共有と、ミックスドシグナルの協調シミュレーションは、後の目標 |
| <a id="ngspice"></a>ngspice | SPICE の方言が違うところで kirimaspice が合わせる、オープンソースの SPICE シミュレータ。参照のために、版を記録して動かすことがある（[NETLIST_CONVENTIONS](spec/NETLIST_CONVENTIONS.ja.md) では ngspice-47） |
| <a id="expected-value"></a>期待値 | テストが確かめる値。モデルの仕様、解析解、記録した参照の実行から決め、既存の期待値の変更は、独立したコミットと人の承認が必要（[AI_POLICY](spec/AI_POLICY.ja.md)） |
| <a id="known-failures"></a>既知の失敗 | `tests/known_failures.txt`：今は失敗するテストの一覧。`tools/local_ci.py` は、ほかの失敗があるときと、起動できなかったテストがあるときに失敗する |
| `local_ci.py` | `build/` で構成、ビルド、テストを行い、失敗を既知の失敗と比べ、`check_banned.py` と `check_spdx.py` を実行するスクリプト |
| `check_banned.py` | 追跡しているファイル（`--history` ではすべてのコミットの差分、メッセージ、作成者）に、ホームディレクトリのパス、noreply 以外のメールアドレス、ファウンドリの名前、バイナリのファイル、5 MB を超えるファイル、`--private` で渡した非公開の名前がないかを確かめる検査 |
| `check_spdx.py` | プロジェクト自身のコードのファイルが、著作権の行と SPDX のライセンスの行で始まっているかを確かめる検査 |
| `Assisted-by`、`Approved-by`、`Reviewed-by` | コミットのトレーラー。それぞれ、AI のツールが手伝った、人が仕様か期待値を承認した、push の前に人がコミットを読んだ、を表す（[AI_POLICY](spec/AI_POLICY.ja.md)） |
| クリーンルーム | GPL と LGPL のコードを読まず、移植もしないという決まり。KLU と BTF は公開 API を通じてだけ使う |
