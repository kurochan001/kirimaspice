## 出発点

直近のローカル検証は、コミット `75f8cb0` に未コミットのレビュー修正を加えた作業ツリーを、
macOS 27.2 arm64、GCC 16.2.0、CMake 4.4.4 でビルドしたものです。
`python3 tools/local_ci.py --jobs 8 --history` の結果は、登録 1,276 件、合格 1,246 件、
既知の失敗 7 件、スキップ 22 件、無効 1 件でした。失敗 7 件はすべて既存の一覧にあり、ビルド、
公開禁止情報、全履歴、SPDX の検査は合格しました。この作業ツリーでのローカル測定であり、
今回の修正についてほかの環境では確かめ直していません。

修正対象は、モンテカルロの抽選値の反映、パラメータ掃引の include とサブ回路、DC/AC の境界条件と
失敗報告、転送関数とフーリエ解析の境界処理、CLI/WAV の入力検証、Python/REPL の結果管理、
リポジトリの履歴検査の見逃しです。追加した回帰テストは
[test_analysis_edge_cases.cpp](../tests/unit/test_analysis_edge_cases.cpp) と
[test_tool_edge_cases.py](../tests/scripts/test_tool_edge_cases.py) にあります。
これらの合格が、すべてのデバイスモデルの精度を示すわけではありません。

記録時点では、実装修正は未コミットです。文書 22 ファイルの訂正、仕様 2 ファイル内の古い観測記述の訂正、
CI の結果集計の修正は、差分を準備していますが未承認・未適用です。この段落は記録時点の状態なので、
再開時には実際の作業ツリーと承認記録を確認してください。

### 2. CI の判定と比較テストを信頼できる状態にする

- [x] テスト実行ファイルがない場合を成功扱いしないように CI の集計を修正する。`cef412f` で実施
  （コミット前に承認済み）。`tools/local_ci.py` は、CTest が起動できなかったテスト、未知の状態、
  結果ファイルがない場合や読めない場合、テストが 1 件もない実行を失敗とし、古い結果ファイルを
  先に消し、スキップと無効のテストはそのまま扱う。`tests/scripts/test_tool_edge_cases.py` が
  これらを確かめる（古いファイルの削除を除く）。push 後の最初の CI（run 44613253295、
  `e8cc364`、Ubuntu 24.04 の CMake 3.31.6、GCC 13.3.0 と clang 18.1.3）で、同じ形式を書く
  ことを確認した。両ジョブとも 1270 件合格・失敗 6 件（すべて既知）・スキップ 3 件・無効 1 件で、
  `did not run` はなし。3 件目のスキップは `BSIM4ComprehensiveTest.NgspiceComparison` で、
  ngspice がなければ自分をスキップする。CI は ngspice を入れず、Nightly は入れる。
- [x] 比較テスト 20 件を復旧する。`ebde192`、`810c728`、`5097fa0` で実施。テストは `validation/` を
  読み、Linux（x86-64）の clang 20.1.8 と GCC 15.2.0 で 20 件すべてが合格し、CI run 44613253295
  では GCC 13.3.0 と clang 18.1.3 でも 20 件すべてが合格した。ほかの環境は未確認。
  `MOSFET2StageAmplifierValidation.MatchesNgspice` の位相の不一致は、参照データの側にあった。
  そのファイルは、トランジスタが遮断するネットリストから作られ、全周波数で 0 V であり、
  11.7 度は正しい出力の位相だった。シミュレータは、ngspice-45.2 と手計算の小信号解に
  3e-7 dB 以内で一致する。0 V の参照に対して 0 dB を返していた比較ヘルパも直した。
- [ ] モデルファイルの不足による既知の失敗 6 件を解消する。ファイルを追加する前に、出自と再配布条件を
  確認する。
- [x] 残る CMOS のゼロ付近の判定を、解析解と浮動小数点誤差に照らして調べる。`6088f8a` で実施。
  厳密解は 0 V で、-4.1e-25 V は丸め誤差。下限を -1e-12 V まで許し、テストを
  `tests/known_failures.txt` から外した。
- [ ] 残る無効なテストの扱いを決める。対象は BSIM4 過渡解析のテスト。BSIM4 の温度のテストは、
  リポジトリに入れた ngspice-45.2 の参照データ（コミット `7f3bd69`）に対して実行され、Linux（x86-64）
  で Vth 0.65%、Ids 2.41%、Vdsat 2.44% 以内で一致する。VDSAT 分岐のテストは、ngspice-45.2 で
  確認した参照値（コミット `df3b036`）に対して実行される。

完了の証拠は、正しい失敗・スキップの判定、実際に実行される比較、残る例外それぞれの理由と次の作業、
不一致を再現できる記録です。許容誤差を黙って緩めたり、既知の失敗に追加したりして合格させません。

- [ ] 抵抗、RLC 回路、独立電源の動作点、DC スイープ、AC、過渡解析を解析解と照合する。
  電圧に加え、枝電流の符号、単位、保存された結果も確かめる。
- [ ] ダイオード、BJT、MOS の順に検証済みの範囲を広げ、各モデルで対応する効果と制約を明記する。
- [ ] 解析解による確認と ngspice の参照実行を組み合わせ、版、モデルのパラメータ、解析条件、
  関連オプションを記録する。出自の記録がない既存の参照データは調査する。
- [ ] 確認済みの素子、解析、動作条件、許容誤差を、レビューと承認の後に公開文書へ記載する。

完了の証拠は、精度を主張する範囲ごとに、独立した根拠のある期待値を持つ再現可能なテストと制約です。

### 4. 同じ意味の実行経路と失敗時の状態を確認する

- [x] モンテカルロの通常版と高速版を、同一の抽選済み素子値で比較する。
  逐次・並列の両方がある処理では、その一致も確かめる。`test_monte_carlo_paths` が、抵抗と
  Level1 の KP の変動について両経路を 1 回ごとに比較する（コミット `97a4ba7`）。逐次と並列は
  同じシードで同じサンプルを与える（コミット `9b9c19f`）。修正前は 20 回中 19 回が違い、
  修正後はすべて一致し、1 回ごとのシードをテストが確かめる。
- [ ] 等価なトップレベル記述とサブ回路を比較する。CLI が実行する解析では、ライブラリと CLI の経路も
  比較する。パラメータ掃引には、相対パスの include を含める。
- [ ] 0 点・1 点の境界、不正な入力と非有限値、存在しないノードや電源、収束失敗、ソルバーの再利用を
  確かめる。非有限値は `DCBoundaryConditions.NonFiniteDeviceValueDoesNotReportSuccess` が
  確かめる（コミット `4be4e38`）。
- [ ] 失敗が呼び出し元へ伝わり、一時的な電源値やパラメータの変更が定めたとおり復元され、
  過去の結果や途中の結果を新しい成功結果と誤認しないことを確認する。

完了の証拠は、対象の経路を通り、数値結果と失敗時の状態の両方を確かめる、根拠のある回帰テストです。

### 5. 今後の修正を毎回レビューできる形にする

不具合ごとに、次の順序を揃えます。

1. 最小の再現例を作り、観測した失敗を記録する。
2. 仕様、解析解、または版を記録した参照実行から期待結果を確定する。
3. 規則を実装する共通の場所を直し、ほかの呼び出し元にも反映されることを確認する。
4. 回帰テストを追加し、関係する検証を実行して、残る制約を報告する。

人のレビューでは、コードに加え、モデルの意味と期待値の根拠を重点的に確認します。
承認の境界とコミットの決まりは、既存の CLAUDE.md と AI_POLICY に従います。
